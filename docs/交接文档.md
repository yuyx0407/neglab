## 一、工作成果总结

NegLab 是一个 macOS 原生 Objective-C 应用，用于将彩色负片的数字化文件（店扫 TIFF 或相机翻拍 RAW）反相成中性、线性的正片。核心理念是把反相所需的参数从「凭感觉试」变成「可测量、可证伪」。

### 已交付的功能

| 功能 | 说明 |
| --- | --- |
| **图像载入** | 支持 16-bit TIFF / 8-bit TIFF / PNG / JPEG / 相机 RAW（通过 Core Image）/ Imacon FFF |
| **去色罩** | 逐通道密度扣除片基 → 光学密度 → 秩 1 分解求 γ 和 o → 输出线性场景 |
| **零点标定** | 三种方式：自动（画面最亮 0.05%）、手动点选片基、锁定（从标定文件继承） |
| **γ 标定** | 从灰阶卡做秩 1 分解，输出逐通道斜率比 + 中性残差 σ₂/σ₁ + 秩 1 残差 |
| **Y/M/C 滤色片** | 数字放大机的印片滤色片，单位 CC，模拟暗房操作 |
| **印片 (2383) 预设** | 在线性母版之上叠加 2383 印片观感（趾部/直线段/肩部） |
| **批量导入** | ⌘O 多选、拖文件到窗口、打开文件夹扫目录 |
| **胶片条** | 画布下方横向缩略图，点哪张载哪张，逐帧生成 |
| **← / → 导航** | 键盘切上一帧/下一帧 |
| **锁定零点** | 把某一帧的零点锁住供同一批其余帧共用（解决「店扫拿不到片基」） |
| **命令行工具** | `calib_cli`（标定 CLI）、`raw2linear`（raw→线性 TIFF）、`imgtest`（IO 自检）、`mathtest`（数学自检 5 项）、`anchor_check.py`（零点一致性诊断） |
| **开源仓库** | github.com/yuyx0407/neglab，Release v3.0 附 macOS universal 安装包 |


### 修复的关键问题

| 问题 | 根因 | 修复 |
| --- | --- | --- |
| 曝光滑杆调不动 | 显示映射用画面自己的 99.9 百分位当白点，在白点之前乘整体系数会被归一化精确抵消 | 曝光移到白点之后（`hi = 百分位 / 2^EV`） |
| 拖动卡顿 | 「原始负片」渲染与滑杆无关却在每次拖动时重算 | 只在该视图激活时才计算 |
| 滑杆读数不动 | `NegSliderRow` 只在初始化时写一次读数 | 加 `fmt` 属性 + `refresh` 方法 |
| 手动点选点不动 | 代码在 `_haveBase` 为假时把选中项弹回「自动」 | 改为进入等待态，允许用户去点 |
| 卡片宽度参差 | 只靠 stack 的 `alignment = Width` 会退化成内容固有宽度 | 钉死每张卡宽度 = `PANEL_W - 2 * PAD_SIDE` |
| 批量导入只出一张 | `loadPath:` 成功回调复位 `_curThumb = 0`，缩略图队列指针归零 | 删掉那行复位 |
| 缩略图太慢 | `negLoadFrame` 完整解码 45MB 再降采样，每张 2-5 秒 | 改用 `CGImageSourceCreateThumbnailAtIndex` 直接按 160px 解码 |
| 片基估计太慢 | 3×3 中值在 36MP 全图上跑一遍要数秒 | 超 2MP 先 2×2 盒式降采样再算（读数不变） |
| 胶片条空占位崩 | `NSNull.null` 不是 nil，过了 `if (im)` 判空后调 `drawInRect:` 抛异常 | 改为 `[im isKindOfClass:[NSImage class]]` |

## 二、已解决事项清单

以下逐项列出已完成任务及其实现方式。

### 1. 理论审查（`docs/原理与实测.md` 第 5 节）

| 检查项 | 结论 |
| --- | --- |
| 成像方向 | ✅ 对。负片密 = 场景亮（D = γ·logE），Pi 大 → L 大 → out 大，正像 |
| `negFitGamma` 里的 `L` | ✅ 命名误导但数学无误（除以 `g[1]` 是秩 1 系数） |
| `lRef = −mean(o_c/γ_c)` | ✅ 与文档一致 |
| `negLCoord` 不减 `lRef` | ✅ 不矛盾（残差只看通道差，lRef 是公共项） |
| 基部 `L<0` 钳位 | ✅ 刻意为之，消除基部染色 |
| 百分位按真实值域分箱 | ✅ 正确 |
| `GAMMA_OUT = 0.6` | ✅ 就是负片 gamma，除以它输出恰好线性（`L = γ_G,真 × logE`） |


### 2. 与中文社区的对照（`docs/参考文献.md` 第 10–13 节）

- **V777**（DiVERE 作者）的「原色集」= 本项目的 `Pi_c = o_c + γ_c·L`，六自由度（3 gain + 3 gamma），「对数域中的平移与旋转」。
- **黄昊Haosky** 的 Cineon 路线补充了我们缺失的常数：18% 中灰 = code 470、密度差 0.3 = 透射光量 ±1 倍。
- **三色窄光谱 LED 光源**能削弱染料层串扰（设备相关部分），使 γ 跨设备更可迁移。
- **刘磊** 指出串扰发生在**取对数之前**（透过率域按波长积分），密度域的 3×3 矩阵只是近似。
- **色罩的物理机制**：有色耦合剂（Colored Coupler）——染料生成量与耦合剂消耗量一一对应，不完美吸收总量恒定，所以 `o_c` 是常数。
- **措辞修正**：橙色色罩不是片基的一部分，是品红+黄色染料组成的校正蒙版。

### 3. 工业界对照（`docs/参考文献.md` 第 9 节）

| 工业界 | NegLab |
| --- | --- |
| ARRISCAN 把 RGB 灯校准到片基最透明处 | 零点 T0（每帧点片基） |
| ARRI 出厂为 20 种胶片标定扫描仪 | γ（每「型号 × 链路」一次） |
| 0.002 D/code、片基 code 95、参考白 code 685、负片 gamma 0.6 | 密度刻度、`L_ref`、`GAMMA_OUT = 0.6` |
| LAD 控制片 / TAF | 灰阶卡 |
| IDT（设备表征，SMPTE 标准范围外） | 灰阶秩 1 分解 |
| ODT / 3D LUT（观感） | 导出后调色 |


### 4. 店家沟通的实践验证

- **Noritsu HS-1800 在 35mm 上确实扫不到片基**：靠掩膜挡住画幅以外（专业冲洗店公开说明可查）。
- **哈苏 Flextight X5** 的 35mm 胶条夹扫描窗 24×226mm，24mm 正好是画幅高，齿孔区被挡。
- **解决方案**：在胶卷开头盖镜头盖空拍一格——未曝光胶片在画幅正中间，掩膜挡不住。前提是店家关掉全部自动项。
- **用用户自己的 gold200 扫描件实测**：39 帧全部 4756×3153（36:24），边框不是片基（远低于最亮处）。店家没有做逐帧自动色阶（直方图两端没被钉死），也没有做逐帧自动白平衡（最亮区颜色在帧间有变化）。

### 已知风险

1. **AppKit 方法在后台线程调用会抛异常** —— `imageFromRGBA:` 不要放后台

4. **带 `cp` 备份的命令不要和 `git checkout` 串在同一条链里** —— 沙箱可能执行两遍

### 技术栈

- **语言**：Objective-C（ARC），不依赖任何第三方库
- **界面**：AppKit 原生（NSWindow / NSView / NSSegmentedControl / NSButton）
- **图像解码**：ImageIO（TIFF/PNG/JPEG）+ Core Image（相机 RAW）+ 自定义 TIFF 读取（FFF）
- **构建**：clang -O2 -fobjc-arc，universal binary（arm64 + x86_64），macOS 12+
- **数学**：手写 Jacobi 特征分解（3×3 对称阵），不引入 LAPACK

### 核心公式

```
密度：    Pi_c = −log10( T_c / T0_c )          T0 = 片基透过率（零点）
拟合：    Pi_c = o_c + γ_c · L                  秩 1 分解求 o 和 γ
反相：    L_c = (Pi_c − o_c) / γ_c − L_ref
输出：    out = 10^( L_c / NEG_GAMMA_OUT ) − 1   NEG_GAMMA_OUT = 0.6
印片：    D_p = negPrintLook( out )              2383 观感（第二层，可选）
          out = 10^(−D_p)
滤色片：  L_c → L_c − d_c                        d_c = CC / 100
```

### 关键设计决策

1. **`NEG_GAMMA_OUT = 0.6` 就是负片 gamma**，除以它恰好输出线性场景（`L = γ_G,真 × logE`，当 γ_G,真 = 0.6 时 `out = E`）。这不是显示 gamma，不是印片 gamma，是**去负片 gamma 的除数**。不能改。
2. **印片 (2383) 是第二层**，在第一层（线性母版）之上叠加。不是替换 `0.6`。
3. **CYM 加在 `L` 上**（`L_c → L_c − d_c`），与本项目的 `o_c` 同构。「CYM 归零」= 标定中性点。
4. **γ 归一化到绿通道**（`γ_G = 1.0`），`L` 的尺度因此等于「负片绿通道的真实密度」。
5. **片基估计 >2MP 先降采样**（2×2 盒式），36MP 从数秒压到零点几秒，读数不变。

2. **跑一次「空白格 + 关自动」的完整流程**：找店家扫一格空白片基，验证「锁住零点」是否有效
3. **清理 `negInvert` 的 `exposure`/`black` 死参数**：改签名需要同步 `calib_cli` / `imgtest` / `mathtest`

### 中期（需要外部资源）

1. **取 2383 高分辨率曲线数据** → 定准印片总反差 → 实现真正的相纸预设
2. **加哈苏 3F 读取器** → 解决「店扫拿不到片基」

### 接手者需要知道的三个教训

1. **任何自带自动白点/自动归一化的显示链路，都会静默吃掉全局增益控制** —— 加滑杆前先检查它作用在归一化的哪一侧
2. **带 `cp` 备份的命令绝不能和 `git checkout` 串在同一条链里** —— 沙箱可能执行两遍，第二遍用已回滚的文件覆盖草稿
3. **写完两批代码才第一次运行是最危险的** —— 加完一个控件就冒烟测一次，一次就能二分定位崩溃点
