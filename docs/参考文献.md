# 参考文献与外部依据

本项目的每一条做法都尽量找外部依据。下面列出**我们测的东西**与**别人写的东西**的对应关系。

---

## 1. Cineon（数字负片格式）

**我们的做法**
- 片基 = code 95，参考白 = code 685，2% 黑 = code 220
- 每 code = 0.002 D，满量程 2.048 D
- 三通道**共用**负片 gamma 0.6
- Cineon 是**印片密度**（printing density）

**外部依据**
> "the 90% white card has a code value of 685, the 18% gray card has a code value of 470,
> and the 2% black card has a code value of 220. These target code values assume that the
> scanner was calibrated to a code value of 95 for D-min."
>
> "With a typical negative film gamma of 0.6, each stop in exposure offsets the Digital
> Negative by 90 code values (in the midscale)."
>
> "The Cineon Digital Negative is represented in printing density, which is to say, the
> density that is 'seen' by the print film when the negative is printed with a standard
> illuminant. The illumination and color filters in the Cineon scanner were designed so
> that the effective spectral response of the scanner matches that of print film."

— *Color and Mastering for Digital Cinema*（Kodak 章节）

另一份独立复述（Bill Spitzak）：
> "Each number in the file is supposed to represent .002 times the base-10 logarithm of the
> density of the film. They also document that the negative's density is proportional to the
> amount of light that struck the film raised to a power called the 'gamma' of the film,
> which is about .6."
> 正确换算：`pow(10.0, (x − W) * 0.002 / gamma)`，其中 W = 685。

**结论**：我们的 Cineon 实现与官方手册逐条吻合。
「Cineon 假定输入是线性透过率」这一点，也由「扫描仪光谱响应匹配印片」这条设计目标支撑。

## 2. RawTherapee Film Negative（**与我们同构**）

这是最重要的一条外部依据。

**它的源码级模型**
```
R = (R ^ rexp) * rmult          rexp = refexp × rratio
G = (G ^ gexp) * gmult          gexp = refexp
B = (B ^ bexp) * bmult          bexp = refexp × bratio
```
即 **每通道一个指数**，而界面上的 `Red ratio` / `Blue ratio` 就是
「该通道指数相对参考指数的比值」= **我们的 γ_R/γ_G 与 γ_B/γ_G**。

**它的官方文档**
> "Ratio of the Red channel exponent to the reference exponent. This coefficient indicates
> how 'bent' the Red channel transfer curve is, with respect to the Green transfer curve."

**它的作者对数学的描述**
> "it's exponential: k*(1/v)^p. And those k's and p's are different for color channels
> R, G and B. If you find them, you can do the inversion based on the real physics of the film.
> To do this, you should give the program two points for which you know for sure they are
> neutral gray, then it builds system of equations and finds the k's and p's so the points in
> the inverted color space are really neutral gray."

**★ 关于「什么是一次性、什么是每帧」—— 直接印证我们的结论**

官方文档：
> "Picking the spots needs to be done only once per film roll, then the processing profile
> can be copied and pasted onto the other photographs from the same roll."

作者本人：
> "do not confuse these coefficients with white balance, they are absolutely different things.
> The coefficients provide more or less invariant constraints for the whole roll, while white
> balance is set up differently for each frame because it shows how the colors were distributed
> in that particular scene with that particular lighting."

**关于取样点数量**（我们的做法更稳）
> "The points should be of brightness different enough (say, neutral black and neutral gray),
> otherwise film grain, which brings a source of error into the equations, will skew the
> coefficients, as the two points will be too close numerically and so any small random noise
> from grain will introduce large errors into the answer."

RT 固定用 **2 点**；我们用 **≥6 点做秩 1 分解**，每多一块灰多两组约束。

**关于拍灰阶卡的建议**（和我们一样）
> "another approach you may follow in the future is to capture a color checker chart on the
> first frames of a film roll which you can later sample (it has a row with gray cells of
> different brightness)."

**关于「点胶片帧本身」**（和我们一样）
> "click the 'Pick white and black spots' button, then click the whitest and blackest spots
> in the actual image - these can be spots in the actual image captured on film, or
> **exposed and unexposed areas of the film frame itself**."

来源：
- rawpedia.rawtherapee.com 的 *Film Negative* 词条
- discuss.pixls.us 关于 film negative 的长贴（rom9 = 作者）
- ipalopezhentsev.github.io/photo/rawtherapee/software/2020/06/14/inverting-in-rawtherapee.html

## 3. darktable negadoctor

**我们复刻的公式**（`src/iop/negadoctor.c:238–322`）
```
默认参数：film_stock=COLOR, Dmin=1.0, wb_high=wb_low=1.0, D_max=2.046,
         offset=-0.05, black=0.0755, gamma=4.0, soft_clip=0.75, exposure=0.9245

commit_params：d_wb_high = wb_high / D_max
              off_c      = wb_high * offset * wb_low
              d_black    = -exposure * (1 + black)
_process_pixel：log_den = -log10(Dmin / max(pix, 2**-32))
              de        = d_wb_high * log_den + off_c
              pl        = max(-(exposure * 10**de + d_black), 0)
              pg        = pl ** gamma
              out       = pg > soft_clip
                          ? soft_clip + (1 - exp(-(pg-soft_clip)/(1-soft_clip))) * (1-soft_clip)
                          : pg
```

**注意**：`gamma` 是**一个数**（4.0），不是逐通道的。
逐通道参数只有 `wb_high` / `wb_low` —— 它们的语义是**增益**，不是「斜率」。

来源：darktable 5.6.1 源码

## 4. DiVERE

**它的色卡机制**（这一条我们更正过一次）
`divere/utils/colorchecker_loader.py` + `config/colorchecker/` 里有**按胶片型号**预置的
CC24 参考数据（8 支常见柯达卷 + original），UI 里有一个 **ColorChecker Selector**。
**它确实能用色卡，也确实有绝对锚。**

但那个锚有三个前提：
1. **参考值是模拟出来的，不是测你的卡**。JSON 原文：
   > 「ColorChecker 24+CIE D55光源在 kodak_gold_200_auc_noDIR→kodak_endura_premier_d60_uc
   > **打印流程**下，相纸上得到的**理论**密度（并取指数）」
   类型字段是 `DensityExp`。
2. 你必须**知道并选对胶卷型号**。
3. 它假定了一套**特定光源 + 特定印片链**（D55 → Endura Premier）。

它校准的是**颜色**（18 个彩色块的 CCM/IDT），不是把「零点」当成一个可测量。

**它的自我陈述**（README）
> 「负片在串扰被正确补偿时，灰阶是无偏色的，校色不需要调整通道 gamma，仅需要调整 RGB 曝光」
> 「推荐使用任何三色窄光谱光源进行翻拍/扫描」
> 「IDT转换和数字Mask可由日光直射的24色卡校正。参考色（实际上是参考密度）由光谱物理模拟+官方数据计算所得。」

来源：github.com/V7CN/DiVERE

## 5. Filmeon

DCTL 是加密二进制，只能照它的 README 复刻模型：

1. 扫描转密度（Cineon 标尺，DMIN 在 95/1023，0.002 D per code）
2. 取片基 Dmin + 两个中性点；**每通道眩光补偿 = 透过率域的加性偏移**
3. 线性化趾部
4. `D = γ·logE + D_min`（γ ≈ 0.6）
5. 密度 → 场景线性：**Cineon 公式**（D=0→E=0，D=1.18 above Dmin→E=1.0）
   或 **Josh Pines 公式**（D=0.7 → E=0.18）
6. 两个 3×3 矩阵
7. 色调映射

**眩光那一条值得单独记**（它自己的说法）：
> "We model this effect as an additive (offset) in the scan (transmittance) space, which
> translates to a non-linear shoulder-like compression in highlights in density space.
> Worse still, it's different per channel, resulting in a color cast in highlights."

它仓库里还带了 `simulated-scans/` —— 4 支已知胶片的 **16-bit 线性灰度梯度**，
这是本项目唯一能用来「判方法对错」的地面真值。

来源：github.com/helios1138/filmeon

## 6. SpektraLab / spektrafilm

应用本身无法无头驱动，但它随包发布了 **28 份明文 spektrafilm 档案**
（Andrea Volpato，CC BY-SA 4.0，v0.3.2）：

| 字段 | 内容 |
|---|---|
| `wavelengths[81]` | 380–780 nm，每 5 nm |
| `log_sensitivity[81][3]` | 三通道光谱感光度 |
| `channel_density[81][3]` | **三层染料的光谱密度**（色罩与串扰的物理来源） |
| `base_density[81]` | 片基光谱密度 |
| `density_curves[256][3]` | 三通道特性曲线 |

**实测结论**：它的**曲线形状**是真的，但**标量数值**与仿真灰阶实测有两成左右偏差。
所以它的价值在**光谱结构**，不在标量数值。

来源：SpektraLab 应用包内 `Resources/engine/profiles/*.json`

## 7. 其它

- **ADX（SMPTE ST 2065-3）**：假设扫描仪已校准到印片密度；ADX16 范围 ≈8，ADX10 ≈2.046
- **Kodak Photo CD**：每通道完整反演各自曲线的做法，也就是本项目里的 `film terms`

  反射确认（见 README「开发者注记」）。`inputBoost = 0` 表示线性响应、不做 boost，

- **ITU-R BT.709 / IEC 61966-2-1（sRGB）**：8-bit 扫描件按 sRGB 传输函数反解为线性，
  是本项目对「8-bit 输入」的唯一假设。

## 8. 我们自己原创的部分

下面这些**没有找到外部依据**，是八轮实测自己做出来的：

1. **零点漂移的量化**：同一卷、同一批扫描之内，零点就漂 **0.37~0.49 档**
2. **Pareto 结论**：参数不确定性 ≫ 方法差异（0.5~20 档 vs 0.1~0.3 档）
3. **PI_CLIP 的副作用**：逐通道截断会制造最多 1.08 档假偏色
4. **秩 1 分解 + σ2/σ1 作为「点数够不够中性」的读数**
5. **「反射灰阶卡 vs 透射靶」的分工**：反射卡校准「胶片+链路」（色罩要的），
   透射靶校准「采集链路」（颜色准确度要的）
6. **中性残差的定量定义**：`ΔL × 0.6 / log10(2)`（见 `docs/原理与实测.md`）。
   公开资料里找不到把「剩余偏色」折算成档来做验收的做法。

## 9. 工业界的依据：印片密度、LAD、ACES

这一节回答一个问题：**好莱坞的胶片数字化流程，色彩与明度曲线的依据到底是什么？**
查完之后会发现，它和我们这套东西是同构的 —— 差别只在终点不同。

### 9.1 起点：负片不是「颜色」，是三层染料的密度

ARRI 的《Digital Intermediate Companion》把这个前提摆得很直白：

> 彩色负片三个感光层的密度，**既不直接对应原场景的色度，也不直接对应最终正片的色度**。
> 那么扫描仪应该怎样把负片里的颜色信息翻译成数字？

同一份手册还有一句，几乎就是本项目第一步在做的事：

> 扫描仪看到的**既不是胶片密度，也不是场景亮度，而是胶片透过率**，
> 必须把它换算成一个照相上有意义的量。

本项目的 `Pi_c = −log10( T_c / T0_c )` 就是这一步。

### 9.2 依据一：印片密度（Printing Density）

工业界选的参照不是「人眼看到什么」，而是**正片会看到什么**：

> 设想一台密度计，它的光源光谱与印片机光源完全一致，红绿蓝三个传感器
> 的感光特性与正片材料完全一致 —— 这台密度计量出来的就是印片密度，
> 即**正片「看到」的密度**。

所以扫描仪的光谱响应被设计成尽量贴近**印片过程的光谱响应**，而不是贴近人眼。

与之并行的另一套参照是 **ISO Status M**（实验室控片用）。两者不同：手册里明确写
「**印片密度「看到」的红密度比 Status M 更多**，用印片密度做出的扫描整体偏暖」。
还有一句特别醒目：

> 在很多场合，**印片密度是靠「把 Status M 数据里的红通道 gamma 抬高」来近似的。**

—— 「逐通道斜率不等、红通道要单独处理」，和我们测出来的 γ = 0.933 : 1 : 1.626 是同一件事。

### 9.3 依据二：明度曲线就是对数，锚点是片基与参考白

Cineon / DPX 把这条曲线写死，用的全是物理量：

| 常量 | 值 | 含义 |
|---|---|---|
| 密度刻度 | 0.002 D / code | 10 bit 的每个码值代表多少密度 |
| 片基 | code 95 | 未曝光片基，密度轴的原点 |
| 参考白 | code 685 | 90% 白，相对亮度定为 1.0 |
| 负片 gamma | 0.6 | 密度与对数曝光之间的换算系数 |

编码本身是 **log 的**（DPX 是「负片密度的线性表示」，因此对数是场景亮度的线性表示）。
**「明度曲线的依据」就是这个：密度是对数的，所以曲线是指数的；锚点只有两个 ——
片基与参考白。** 它不是一个审美选择。

本项目的 `GAMMA_OUT = 0.6` 直接来自这里；`L_ref` 就是那个白点。

### 9.4 依据三：用控制片做设置与核查（LAD / TAF）

**LAD（Laboratory Aim Density）** —— Kodak 出品的控制片，中间一大块灰：

- 目标：这块灰印到正片上得到**中性灰、视觉密度 1.0**。
- 印片条件：控制片一律打在**印片机行程的中点**（加色印片机通常 TAPE 25-25-25）；
  其余场景再相对它做配光。
- 对中间片另有具体目标（Status M 密度，例如 Master Positive 红 1.15 / 绿 1.60 / 蓝 1.70，
  取在感光曲线直线段的中央）。

其中一句几乎就是我们想说的话：

> **LAD 控制片是用来给电子配光机和印片机做设置的。它不是「每个场景都必须匹配」的参照。**

胶转磁（telecine）用的 **TAF（Telecine Analysis Film）** 是同一个思路：一条灰阶加上
一个带 LAD 灰底的八条彩条，用途是**把 telecine 居中**。

### 9.5 依据四：ACES 把「测量」与「观感」明确分开

ACES / SMPTE ST2065-1：

- **IDT / ACES Input Transform**：把设备数据搬到 **ACES2065-1** —— 场景线性、宽色域、**没有曲线**。
- **ODT**：把 ACES 映射到具体显示设备，**这才是曲线与观感所在**。
- 标准原文：

> ACES 图像不能直接用于最终画面的评估，**正如胶片负片、或以印片密度编码的文件
> 不能直接作为最终画面观看。**
>
> 把实拍或合成的曝光转换成 ACES 相对曝光值，需要一套**对采集设备做表征**的流程。
> **这些流程不在本标准范围内。**

最后这句是关键：**连电影艺术与科学学院的标准，都把「你的设备到底怎么响应」这件事
明确地留在标准之外，由实施者自己测。** 所以「科学性依赖标定环节」不是本项目的缺陷，
是这个领域的物理决定的。

### 9.6 与 NegLab 的对应关系

| 工业界 | NegLab |
|---|---|
| ARRISCAN 扫之前把 RGB 灯校准到**片基最透明处**（现场经验，见 9.8 末尾） | 零点 T0，每帧点片基 |
| ARRI 出厂为 **20 种胶片**逐一标定扫描仪 | γ，每「型号 × 链路」一次 |
| 0.002 D/code、白点 685、负片 gamma 0.6 | 密度刻度、`L_ref`、`GAMMA_OUT = 0.6` |
| LAD 控制片 / TAF | 灰阶卡 |
| 设备表征（IDT，标准外） | 灰阶秩 1 分解 |
| ODT / 3D LUT —— 观感 | 导出后你在达芬奇 / Photoshop 里调 |

顺带一提，ARRISCAN 那条校准有个明确的作用：**把不同机器之间因光源差异造成的差别压下去。**
这和我们说「γ 管一条链路」是同一个道理 —— 标定是把不可比变成可比的工具。

### 9.7 一处刻意的不同：终点不一样

工业界的终点是**印片的样子**（output-referred，ACES 里叫 Academy Print Density）；
本项目的终点是**中性的、可以继续调色的正片**。所以 LAD 的中间片目标是
红 1.15 / 绿 1.60 / 蓝 1.70 这种**三通道不相等**的值 —— 那是中间片的成像目标，
不是「不中性」。

**采集端的依据完全一样，只是交付目标不同。** 这一点也提醒我们：NegLab 输出的是
中间物，不是成品；成品那一步（曲线、观感）本来就应该由调色环节决定。

### 10.2 最扎心的一条：削顶问题 2019 年就写在中文博客里

cooltowel 那篇的原文：

> 网上很多翻拍的教程告诉我们，翻拍时要向右曝光，这样才能榨干相机的动态范围。
> 一开始我也是这样做的，但是这会引发一个巨大的问题 —— 明明在扫描仪扫出来的图像上
> 非常好用的去色罩方法失灵了。图像仍然蒙着一层蓝色……
> **向右曝光使色罩变得更浅！**
> 考虑一个极端情况：片基溢出为白色，但是其他地方不会溢出，仍有色罩。
> 于是取片基色（此时片基色为白色）再将其减去的方法自然就失效了。

**这与本项目 2026-10-01 从用户 NEF 上诊断出的问题是同一个**：R 通道 12.3% 的像素
超过 1.0、片基被削成平顶、零点被解成 1.00001。我们当时把它当成一个新发现；
实际上 2019 年就有人写清楚了。

作者给的解法也几乎一样：先测「裸光刚好不溢出」的曝光，再测「片基刚好不溢出」的曝光，
记下两者之差 Δ，回 ACR 降 Δ 曝光。**这就是本项目 `rawToCGImage` 里那趟自动 EV
补偿的手工版本。**

同一篇的 2021 年补注还确认了一条我们坚持的做法：

> 正确的去色罩的操作应当在线性空间完成，而非经过非线性映射后的普通的 RGB 空间进行。

### 10.3 NexFilm 的管线，对照本项目

它的 v1.1.0 把管线写成：

```
输入域判定 → 逐通道扣除片基 → 光学密度 → 共享窗口原点 → 有界通道跨度响应 → 输出
```

| NexFilm 的说法 | 本项目对应物 |
|---|---|
| 逐通道扣除片基 | 零点 T0 |
| 光学密度 | `Pi_c = −log10(T_c / T0_c)` |
| 共享窗口原点 | `L_ref`（三通道共用的参考点） |
| **有界通道跨度响应** | `γ`（逐通道斜率）—— 但它**带界限**，且「只在三通道确实失衡时介入」 |

**分歧点正好落在我们验证过的地方。** 本项目实测过：逐通道**硬截断**（密度上限取 1.8）
会凭空制造 **1.081 档**假偏色，因为截断是逐通道分别生效的。「只在三通道确实失衡时介入」
说明作者知道这个风险，但「有界」具体怎么界，README 没有展开 ——
**这是值得读源码或拿实测数据去撞的地方。**

### 10.4 它比本项目多的（我们确实缺）

1. **整卷批处理** —— 按整卷最亮的真实画面定一个共享白点，一卷约 2 分钟。
2. **片头片基标定** —— 用片头（纯片基）标定、整卷套用。与本项目给的「空拍一格」是同一思路，
   但它是内置功能。
3. **参数复制到其他帧** —— 本项目 2026-10-01 才加上「锁定零点」，它早已有。
4. **硬件校正（仍标实验性）**：dark / **open gate** / flat / 透射目标 ——
   **这一整层本项目完全没有**：
   - dark = 暗场（传感器本底）
   - **open gate = 无片裸光**（正是「用裸光源当零点」那条路）
   - flat = 平场（照度均匀性）
   - 透射目标 = 透射色靶，用于拟合 3×3 分离矩阵
5. **输入域逐帧解析并记录**（内嵌 ICC / 扫描仪容器记录 / RAW 元数据 / 机型识别 / sRGB 兜底）——
   本项目只是按位深判线性还是 sRGB。
6. **输出格式**：线性 16 位 TIFF、**线性 DNG**、**相机 RAW DNG**（原样封装扫描的 RAW 马赛克）；
   可嵌入 sRGB / Display P3 / Adobe RGB / Rec.2020 / ProPhoto RGB / ACEScg / ACES2065-1。
7. **流式解码** —— GB 级 FFF / 扫描 TIFF 不全幅驻留内存。本项目的 `raw2linear` 是全幅进内存的。
8. 打印胶片模拟 LUT（Kodak / Ilford）、接触印相、波形图、透视与拉直。

### 10.5 它没提、而本项目相对更可验证的地方

NexFilm 提到「Capture Separation 3×3 可由实测色卡拟合」—— 那是**颜色变换**
（ΔE 那件事），不是**斜率标定**。它的 README 里没有出现用中性灰阶定量求 γ
并给出残差指标的做法。

本项目这边有三个**可证伪的读数**：σ₂/σ₁（这批点够不够中性）、六点中性残差、
跨帧套用的样本外检验。这是本项目目前最实在的相对优势：
**不是算法更强，而是每个结论都能被推翻。**

### 10.6 因此该补的四件事

1. 读那篇知乎（理论源头），确认有没有我们没覆盖的东西。
2. 搞清楚它的「有界通道跨度响应」到底怎么界 —— 对照本项目的 PI_CLIP = 2.5 结论。
3. 补上硬件校正那一层：**dark / open gate / flat**。这是本项目唯一完全空白的维度，
   而且 open gate（裸光源）能直接解决「店家扫不到片基」时零点的来源问题。
4. 输出补 **线性 DNG**（自描述色彩空间，比裸 TIFF 省事）。

## 11. 硬件校正：dark / flat / open gate / 透射靶

NexFilm 的「硬件校正」在它的 README 里只列了四个名词，没说原理。这一节补齐 ——
**这是本项目完全没有的一层。**

### 11.1 它要标定的不是胶片，是「采集链」

整条管线默认：

```
测得值 ∝ 光源光谱 × 胶片透过率 × 传感器响应
```

现实里还挂着三个东西：

1. **加性偏移** —— 传感器的本底（黑电平、暗电流、热像素）
2. **空间不均匀** —— 灯箱的照度不均 + 镜头暗角 + 传感器各像元响应不均
3. **参考点缺失** —— 「100% 透过率」在画面里没有落脚处

硬件校正就是把这三种东西先在**采集侧**标掉，让后面的密度数学成立。

### 11.2 四项各自是什么

| 项 | 怎么拍 | 数学 | 依据 |
|---|---|---|---|
| **dark** 暗场 | 盖上镜头盖 / 关灯 | `raw − dark` | 传感器输出 = 增益 × 信号 + **本底**。不减本底，响应就不过原点，暗部密度被压缩。天文与显微摄影的 dark frame 是同一件事 |
| **flat** 平场 | 拍一个均匀无特征的场（裸光灯板，或离焦的均匀面） | `(raw − dark) / (flat − dark)` | 测得值 = 照度(x,y) × 胶片(x,y) × 传感器(x,y)。除掉与位置有关的那部分，剩下才是胶片。同样是天文 / 显微的标准公式 |
| **open gate** 无片裸光 | 片门空着，直接拍光源本身 | 把这一帧定为 **T = 1** | 裸光背后没有胶片，这就是「100% 透过率」的**物理定义**。有了它，密度变成**绝对光学密度**（片基密度含在内） |
| **透射靶** | 透射式灰阶 / 色靶，放在灯箱上、**与胶片共用同一光路** | 与证书密度值比对 | 反射灰卡只能用胶片拍；透射靶可以摆在灯箱上，与胶片共享光源、几何与传感器 —— 所以它标定的是**采集链本身** |

### 11.3 open gate 是最值钱的一条（也是本项目的关键缺口）

本项目一直说「零点必须每帧都有片基」。open gate 把这件事整个换掉了：

设裸光那一帧的读数为 `raw_open`，则

```
T_c = raw_film / raw_open        →     Pi_c = −log10(T_c)  =  绝对光学密度
```

三个后果：

1. **零点从「逐帧估算」变成「一次标定、全程精确」。** 片基的密度不再是待估量，
   而是自动进入模型里的偏移 `o` —— 而 `o` 本来就是要拟合的。
   回到第 5 节的误差公式：`err = D0_true − D0_assumed`，用 open gate 时
   **D0_assumed 恒等于 D0_true，err 恒为 0**，跨帧转移不再有零点误差。
2. **它同时完成了平场校正。** 照度 I(x,y) 与传感器响应 S(x,y) 在
   `raw_film` 与 `raw_open` 里是**同一个因子**，相除时精确抵消：

   ```
   raw_film(x,y) = I(x,y) · T_film(x,y) · S(x,y)
   raw_open(x,y) = I(x,y) ·                 S(x,y)
   T_c(x,y)      = T_film(x,y)          ← 照度与传感器不均匀性一起消掉
   ```

   所以在灯箱翻拍里，**open gate 与 flat 可以是同一张**（裸光板既是「没有胶片」，
   也是「均匀场」）。
3. **它正好解决「店家扫不到片基」。** 前提是自己翻拍 —— 店扫拿不到 open gate，
   那是店家机器的内部状态。

**一个前提**：open gate 那一帧**不能溢出**。最亮的地方一旦削顶，分母就废了。
这正是 cooltowel 那篇 2019 年博客里「先测出裸光刚好不溢出的曝光」那一步的理由 ——
那条线、NexFilm 这条线、和本项目从误差公式推出来的结论，在这里汇合了。

### 11.4 边界：这套东西什么时候不成立

- **只对固定机位的自翻拍成立。** 店扫的 dark / flat / open gate 你拿不到。
- **每一帧必须同参数**：曝光、光圈、光源、白平衡全部锁死，关掉一切自动。
  open gate 的「一次标定」是建立在「所有帧共用同一次采集条件」上的。
- **换灯、换镜头、改曝光 → 全部重做。**
- **NexFilm 自己把这套标成实验性**，README 原文：「该功能仍在开发，当前不稳定，
  请不要将其投入严肃使用。」所以方向是对的，但**尚未被公开验证**。

### 11.5 与本研究数学的接口

这一层**不改动本项目的数学**，只是喂给它更干净的数据：

```
T_corrected = (raw − dark) / (flat − dark)        或        raw_film / raw_open
```

之后 `Pi = −log10(T/T0)`、秩 1 分解、中性残差全部照旧。

### 11.6 顺带更正：@V777 就是 DiVERE 的作者

用户指出：`github.com/V7CN/DiVERE` 的 V7CN 就是知乎的 @V777。这一点很重要 ——
说明中文社区那条线**与本项目第 4 节读过的是同一条**。我们不是完全没碰，
而是**只读了它的代码与 README，没有读它背后的理论讨论**（知乎那篇、以及散在各处的中文博客）。

DiVERE 自己的断言值得单独记下来，因为它与本项目有直接分歧：

> 负片在串扰被正确补偿时，灰阶是无偏色的，**校色不需要调整通道 gamma，仅需要调整 RGB 曝光**

见 `原理与实测.md` 第 4.6 节对这个分歧的分析。

### 11.7 dark 与 flat 各自在防什么（展开）

把采集侧的完整算式写开，两者管的段落一目了然：

```
raw_c(x,y) = g_c · t · ∫ I(x,y,λ)·T(x,y,λ)·S_c(λ) dλ · V(x,y)   +   b_c(x,y)
                                                    ↑ 乘性·与位置有关      ↑ 加性·本底
                    └──────────── flat 管这一段 ────────────┘   └─ dark 管这段 ─┘
```

标准公式（线性空间，取对数之前）：

```
corrected = (raw − dark) / (flat − dark)
```

**dark 在分子分母都要减**（否则平场自己的偏置会污染除法）；flat 要归一化到均值 1，
否则会连带改变整体亮度。

#### dark（暗场）

- **怎么拍**：盖上镜头盖（或关灯），**参数完全不变**，拍一张；讲究一点拍多张取平均。
- **要减的是两样**：① 黑电平 / 偏置 —— 传感器输出是 `k×信号 + b`，`b≠0` 时响应不过原点；
  ② 暗电流与热像素 —— 多张平均可以压掉固定图样噪声。
- **对去色罩的具体危害**：我们的数学是 `Pi = −log10(T/T0)`，前提是 `raw ∝ T`。有本底时

  ```
  raw = k·T + b   →   raw/raw_base = (k·T + b)/(k·T0 + b) ≠ T/T0
  ```

  T 越小（越密）误差越大 —— **暗部密度被压缩**；而 `b` 各通道不同，压缩量也不同，
  于是**暗部出现通道差**。
- **但要诚实**：走正常相机 RAW 解码器时，黑电平**通常已经被扣掉了**
  （LibRaw、DNG 的 BlackLevel 标签都会处理）。所以这一步多数时候是「确认一下」，
  而不是「一定有东西要扣」。走自定义线性管线时才必须自己减。

#### flat（平场）

- **怎么拍**：一个**均匀无特征**的场。对灯箱翻拍就是**不放胶片的裸光板**。
- **要除掉的是位置相关的乘性因子**：灯箱照度不均、镜头暗角、传感器像元响应不均（PRNU）。
- **反直觉的一点**：**单纯的亮度不均其实不影响 γ 的拟合** —— 模型里每个采样点的曝光
  `L` 是自由参数，照度梯度只是让各点落在不同的 `L` 上。真正会坏事的是三条：
  1. **采样点被推到曲线两端**。边缘暗 20%，那里的灰卡台阶就落在更低的曝光上，
     可能掉进趾部或肩部。校正平场是为了让采样点留在直线段上。
  2. **亮度差与密度差混在一起，无法分辨**「这块比那块暗」是灯的问题还是胶片的问题。
  3. **★ 光的颜色随位置变化时，直接破坏中性**。LED 灯板或扩散板带色偏（常见：边缘偏冷）时，
     两个中性块在不同位置会得到不同的三通道曝光比，灰卡不再落在一条直线上，**σ₂/σ₁ 会炸**。
- **有用的推论**：**σ₂/σ₁ 对「照度的颜色不均」敏感，对「照度的亮度不均」不敏感。**
  灰卡通过 σ₂/σ₁ 只说明那块区域的**颜色**是均匀的，不代表亮度均匀。

#### 灯箱翻拍可以把两张并成一张

```
raw_film = I(x,y)·T(x,y)·S(x,y)
raw_open = I(x,y)·     ·S(x,y)      ← 照度与传感器响应是同一个因子
T        = raw_film / raw_open      ← 两者精确抵消
```

**裸光板既是没有胶片（open gate），又是均匀场（flat）。** 所以相机翻拍只需多拍两张：
盖镜头盖一张（dark）、裸光板一张（open gate + flat）。

**一个抵消不掉的东西：眩光。** 高对比画面里（例如负片上一片过曝的天空），
漏光不正比于透射率，open gate 里没有对应的项，除不掉。这是这套方法的边界。

### 11.7 dark 与 flat 各自在防什么（展开）

把采集侧的完整算式写开，两者管的段落一目了然：

```
raw_c(x,y) = g_c · t · ∫ I(x,y,λ)·T(x,y,λ)·S_c(λ) dλ · V(x,y)   +   b_c(x,y)
                                                    ↑ 乘性·与位置有关      ↑ 加性·本底
                    └──────────── flat 管这一段 ────────────┘   └─ dark 管这段 ─┘
```

标准公式（线性空间，取对数之前）：

```
corrected = (raw − dark) / (flat − dark)
```

**dark 在分子分母都要减**（否则平场自己的偏置会污染除法）；flat 要归一化到均值 1，
否则会连带改变整体亮度。

#### dark（暗场）

- **怎么拍**：盖上镜头盖（或关灯），**参数完全不变**，拍一张；讲究一点拍多张取平均。
- **要减的是两样**：① 黑电平 / 偏置 —— 传感器输出是 `k×信号 + b`，`b≠0` 时响应不过原点；
  ② 暗电流与热像素 —— 多张平均可以压掉固定图样噪声。
- **对去色罩的具体危害**：我们的数学是 `Pi = −log10(T/T0)`，前提是 `raw ∝ T`。有本底时


### 12.1 V777 的「原色集」——与本项目的模型同构

他对「负片有没有原色」这个争论的终结方式很有力：

> 负片一定有原色，但这个「原色」不是一张固定照片，而是**无数种照片的集合**……
> 而且这个集合中的照片有**六个自由度**可调整、相互映射：**rgb 三个通道的 gain 和 gamma**
> （暗房中貌似并不能控制 gamma，但可以通过选择相纸来做出变化）。**也就是对数域中的平移和旋转。**

**这正是本项目的模型。** 我们的 `Pi_c = o_c + γ_c·L` 里，`o_c` 就是 gain（平移），
`γ_c` 就是 gamma（旋转），六个自由度。他用「对数域中的平移与旋转」表达，
我们用「逐通道仿射」表达，**是同一件事的两种说法**。

同一篇里还有三条与我们完全一致的判断：

> **你不能在线性域里碰曲线，哪怕很小一下。**

> **胶片特性曲线中包含了色罩的全部信息**，唯象地可以说成三个色层的感光度与 gamma 不同。

> 色罩根本不该叫色罩，**它并不是一个不变的色糊上去的**。

流程上他给出的六步与本项目逐步对应：

| V777 的六步 | 本项目对应 |
|---|---|
| 1 做一张线性扫描 | 16-bit 线性 TIFF / 相机 raw |
| 2 **先**指定扫描仪色彩空间、再转 ProPhoto RGB | 我们工作在扩展线性 sRGB；**没做输入域判定**（缺口） |
| 3 转到 log 域（自己用 python+OpenCV，参数借 Cineon） | `Pi_c = −log10(T_c / T0_c)` |
| 4 曲线工具反相（为了直方图更宽、好调） | `negInvert` |
| 5 **曲线工具校色：直接改截距与斜率** | **秩 1 分解求 `o` 与 `γ`** ← 同构 |
| 6 log 域调 gamma 与曝光 → 转回线性域调色温 | 曝光 / 黑点滑杆 → 导出线性 TIFF |

他还报了一个很有分量的现象：**校色出来的曲线形状「与官方给的特性曲线非常相似」。**
这等于说「从灰阶拟合出来的曲线」与「厂家公布的感光曲线」对上了 —— 这是一条独立的交叉验证路径。

他也在同一篇里自认了边界：

> 校色最终都是考验眼神的活儿，**这个是教不来的**。

—— 这恰好标出本项目的相对位置：**我们做的事是把「眼神」换成一个能被推翻的残差读数。**

### 12.2 黄昊Haosky 的 Cineon 路线

《浅谈柯达 Cineon》给出的常数比本项目此前掌握的更全（**加粗的是我们原来没有的**）：

- 光学密度 `D = log10(1.0/T)`；**密度相差 0.3 代表透射光量 ±1 倍**
- 10-bit log 编码，**每码值 = 0.002 密度增量，覆盖 2.048 个密度单位**
- **黑点（Dmin）= 95，白点（90% 漫射白）= 685，18% 中灰 = 470**
- **低于 95 的数值代表负片未曝光的片基**；**高于 685 = 比白色更亮的高光**（太阳、金属反光）

他的四步流程（《达芬奇 Cineon 胶片去色罩教程》）：

1. 解 RAW 时挂载**匹配光源的 DCP / ICC**，输出线性（Gamma = 1.0）TIFF
2. 导入达芬奇，线性域 → Cineon Film Log（线性转对数）
3. **在 Cineon 的对数域中反相、对齐三通道**（黑点 95/1023、90% 白 685/1023）
4. 转 Rec709 / Gamma 2.4 恢复亮度与反差（或套 Print LUT）

**第 3 步的「对齐三通道」就是本项目的 γ 校正**，只是在达芬奇里用手调曲线完成。

### 12.3 ★ 三色窄光谱光源 —— 这可能是我们与 DiVERE 分歧的答案

《达芬奇 Cineon 胶片去色罩教程》开头列出的前置文章里，第一篇是：

> **【为什么要用 RGB 三色窄光谱 LED 光源进行胶片数字化/翻拍】**

这一条与第 4 节记录过的 DiVERE README 断言对上了：

> 负片在**串扰被正确补偿**时，灰阶是无偏色的，**校色不需要调整通道 gamma，仅需要调整 RGB 曝光**
> ……**推荐使用任何三色窄光谱光源进行翻拍/扫描**

把两条合起来看，逻辑就通了：

- 胶片三层染料的吸收光谱**互相重叠**（青染料会吸收一部分蓝、品红会吸收一部分绿……），
  这就是「串扰」。用**宽带**光源（白 LED、闪光灯、店扫的灯）时，每个传感器通道都会
  同时看到多个染料层的贡献 → 串扰存在。
- 用**三色窄光谱**（每个通道只取该染料层吸收峰附近的一个窄带）照明时，
  每个传感器通道基本只看到自己那一层的染料 → **串扰被大幅削弱**（不是完全消除，
  因为染料吸收带本身就宽且重叠）。
- 串扰一旦消失，第 4.6 节推出来的 `γ_c = γ' × Σ_j M_cj` 就退化成 `γ_c = γ'`，
  三通道斜率相等 —— **于是「不需要调通道 gamma，只需要调 RGB 曝光」。**

**如果这条成立，本项目的 γ = 0.933 : 1 : 1.626 就是「宽带光源造成的串扰」的读数，
而不是胶片三层本身的斜率差。** 而且它是**可以证伪的**：

> 在自己翻拍时换成三色窄光谱光源，重新解一次 γ。
> 若三通道比值塌回 ≈ 1 : 1 : 1 → 串扰假说成立；
> 若仍然明显偏离 → 假说不成立，斜率差另有来源。

这是第 4.6 节那个「用灰卡分不出来」的问题**唯一可做的判别实验**，值得优先排期。

### 12.4 一个真实的方法论分歧：要不要依赖「片头片尾」

黄昊在同一个问题下的另一条回答里明确反对：

> 此校色法的思路是**分别调整 RGB 三条通道**，以使胶片的高光、暗部、中间调均无偏色，
> 因为是**针对单张计算，不需要片头片尾，无惧同卷底片因曝光量不同导致的密度不同造成的偏色**。

也就是说：中国这条线的主流做法是**逐张调三通道曲线**，靠**画面自身的高光/中间调/暗部
应当是中性**这个假设，而不是靠一张已知中性的参考。

| | 黄昊 / V777 路线 | 本项目路线 |
|---|---|---|
| 中性参考从哪来 | **画面里假设存在的中性**（高光/中间调/暗部） | **灰卡**（已知中性） |
| 需要额外拍东西吗 | 不需要 | 要（一卷一两格） |
| 逐帧还是整卷 | 逐帧 | γ 整链路一次 + 零点逐帧 |
| 失败场景 | 画面里没有中性（大面积单色墙、纯夜景） | 忘记拍卡 / 拿不到片基 |
| 判据 | 「考验眼神」 | σ₂/σ₁、六点残差 |

两者不是谁替代谁：**画面有可靠中性时，逐张法更快；没有可靠中性时，灰卡是唯一出路。**
本项目的价值在于它**可证伪** —— 逐张法无法告诉你「你这次调对了没有」。
