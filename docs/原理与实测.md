# 原理与实测

这份文档回答两件事：**这套数学是怎么来的**，以及**每一个数字是在什么条件下量出来的**。

---

## 一、数学

### 1. 密度，不是亮度

负片承载的信息是**光学密度**，不是透过率：

```
D = −log10(T)           T = 10^(−D)
```

一条 8-bit 的斜线：`T=1.0 → D=0`，`T=0.1 → D=1`，`T=0.01 → D=2`。
所以「把亮度反过来（1−T）」在数学上从头就是错的 —— 那等于在一条指数曲线上做线性运算。

### 2. 色罩（橙色色罩）

C41 彩色负片在冲洗后，品红/黄色成色剂残留了一层固定密度。它的物理表现：

- 三个通道的**片基透过率完全不同**：实测一支真实胶片 `D_base = R 0.27 / G 0.60 / B 0.85`
- 蓝通道被压掉最多（片基透过率常常只有 14%）
- **这是物理必然，不是扫描仪的问题**

因此正确流程是：**先减掉自己这个零点，再谈颜色**。

### 3. 三行核心

```
Pi_c  = −log10( T_c / T0_c )                    ① 相对零点的密度
L_c   = ( Pi_c − o_c ) / γ_c                    ② 逐通道曝光坐标
out_c = 10^( (L_c − L_ref) / 0.6 ) − 1          ③ 反相
```

| 符号 | 含义 | 定一次还是每帧 |
|---|---|---|
| `T0` | 零点：零曝光在密度轴上的位置 | **每帧** |
| `γ_c` | 逐通道密度斜率比 | **一次性**（型号 × 链路） |
| `o_c` | 逐通道偏移 | 和 γ 同时解出 |
| `L_ref` | 黑点锚 | 和 γ 同时解出 |

### 4. 秩 1 分解（怎么把 γ 测出来）

**前提**：在一段中性灰上，三通道看到的是**同一次曝光**（反射率相等、光照相同）。

第 k 级灰的曝光是 `L_k`，则：

```
Pi_R(k) = o_R + γ_R · L_k
Pi_G(k) = o_G + γ_G · L_k
Pi_B(k) = o_B + γ_B · L_k
```

把这写成 `Pi = 1·oᵀ + L·γᵀ`（N×3 矩阵的秩 1 外积）。做法：

1. 每列减去列均值 → 消掉 `o`
2. 对结果做 SVD
3. **右奇异向量 u₁ = γ 方向**（归一化到绿通道）
4. **左奇异向量 × 奇异值 = 公共曝光 L**
5. **σ₂/σ₁** = 残差大小 = 「这批点够不够中性」

**关键性质**：`L_k` 是**与通道无关**的同一个数，所以不需要知道每级灰的绝对亮度 ——
只要它们确实是中性就够。

### 5. 为什么三通道的 L 不能取中位数

写代码时最容易犯的错。取中位数 ⇒ 三通道输出相同 ⇒ **输出变成一张灰图**。

正确做法是**各自保留**：
- 中性处三通道的 L 天然相等 → 输出中性 ✅
- 有色处三通道的 L 不同 → 颜色保留 ✅

一次同时满足「中性」和「不丢色」。

### 6. 为什么跨帧搬运标定时不该给偏移做平移

代数上（`L̄` = 灰阶的平均曝光，`L0` = 该帧零点像素的曝光）：

```
A 帧解出：  o_c = γ_c·(L̄ − L0_A)      L_ref = −(L̄ − L0_A)
B 帧反相：  Pi_c = γ_c·(L − L0_B)
L_c − L_ref = (L − L0_B) − o_c/γ_c − L_ref
            = (L − L0_B) − (L̄ − L0_A) + (L̄ − L0_A)
            = L − L0_B                ← 三通道完全相同 → 天然中性
```

**每帧的零点是通过 `Pi` 自己进去的**，所以 `o` 和 `L_ref` 是常数，不该动。
数值验证：三种「B 帧零点与 A 帧不同」的情形下，输出最大通道差 **0.0000004 档**。

> 我一度加了 `o_B = o_A + log10(T0_B/T0_A)` 的「规范变换」，是错的，已回退。

**唯一会出事的只有两件事：**
1. 这一帧的「最亮像素」不是真正的片基；
2. 那个像素不中性。

这两件事都不是代数能救的 —— 这就是**手动点片基**比自动猜准得多的原因。

## 二、实测数字

### 输入侧

| 项目 | 8-bit 店扫件 | 翻拍 raw → 16-bit 线性 TIFF |
|---|---|---|
| 蓝通道唯一值 | **89**（≈5.6 bit） | **52788** |
| 绿通道唯一值 | 151 | 37827 |
| 红通道唯一值 | 195 | 52788 |
| 密度量化台阶 | **0.0248 D** | ~0.0003 D |
| 撞密度上限的像素 | 最高 **21.2%** | — |

### γ 精度

| 来源 | γ 比 [R, G, B] | 有绝对锚吗 |
|---|---|---|
| 用户灰阶卡（3 条中性列互证） | **0.933 : 1 : 1.626** | 有 |
| 从画面猜斜率 | 0.738 : 1 : 1.770 | 没有（被场景污染） |
| 差值 | **红 0.34 档 / 蓝 0.12 档** | — |

> 所有方法之间的差异只有 **0.1 ~ 0.3 档**。
> 所以「把 γ 从猜换读」的收益 ≈「换一整套软件」。

灰阶卡自身的校验：

| 检查 | 结果 |
|---|---|
| 8 列里通过秩 1 检验的中性列 | **3 列**（其余 5 列是彩色块） |
| 三列给出的 γ 比一致度 | **4% 以内** |
| 六点中性残差 | **≤ 0.049 档** |
| 秩 1 残差 | 0.0396 D |

**「中性残差」的定义**（`app/NegMath.m` 的 `negNeutralResidual`，与 `negInvert`
中真正用到的量一致）：

```
ΔL      = max_c | L_c − L_G |            L_c = (Pi_c − o_c) / γ_c
残差（档）= ΔL × 0.6 / log10(2)          = ΔL × 1.993
```

系数 0.6 是输出端固定的印片 γ，除以 log10(2) 把「十进密度」折成「档」。
所以它的物理含义是：**以 0.6 印片 γ 计，输出密度上还剩多少档偏色**。
阈值取 0.15 档。

早期版本的 Python 代码（`tools/verify.py` 与旧版 PySide6 界面）在这一点上不一致：
界面显示的是「反相之后再取 log2」的散差，量纲虽然也是档，但数值比上式大 2.78 倍，
而且在某个通道被压到 0 时会产生假的天文数字。现在以 C 版本的定义为准，两边已统一。

### 零点漂移（本项目的原创发现）

判据：如果零点稳定，那么「片基密度的通道差」在同一卷内应当是常数。

| 量 | 中位值 | 整卷极差（39 帧） | 折成档 |
|---|---|---|---|
| Dmin_R − Dmin_G | −0.2531 D | 0.1110 D | **0.37 档** |
| Dmin_B − Dmin_G | +0.4124 D | 0.1487 D | **0.49 档** |

**同一卷、同一批扫描之内，零点就漂 0.37~0.49 档 —— 比所有方法之间的差异（0.1~0.3 档）还大。**

而且这**不是扫描仪在漂**（同批各帧的片基通道错开量极差只有 0.32 档），
是**零点从来没被真正测过** —— 只是每帧拿「最亮的那撮像素」当代理。

### 灵敏度

| 扰动 | 结果的偏移 |
|---|---|
| 三通道**等比**的片基误差（动 2 档） | 0.406 → 0.414 档（**几乎无害** —— 等于全局改亮度） |
| **单通道**（蓝）片基估成 ×0.5 | **8.4 档** |
| 只把蓝片基估成 ×0.7 | 2.7 档 |
| 只把蓝片基估成 ×2.0 | 1.6 档 |
| 注入真实店扫的逐通道片基误差 | 8.1 ~ 20.6 档 |

### PI_CLIP（密度上限）

| PI_CLIP | 合成灰阶上凭空多出来的偏色 |
|---|---|
| **1.8** | **1.081 档** |
| 2.5（项目默认） | 0.000 档 |
| 不截断 | 0.000 档 |

原因为：截断是**逐通道分别**生效的，很密的区域会被三个通道以不同的量削掉。

> **一处需要如实说明的地方。** 第八轮那份报告的示意图（`000364980008_chart.jpg`
> 等）在 `grey_card.py` 里用的是 `clip=1.8`，也就是上表里会凭空制造 1.081 档
> 偏色的那一档设置。这个结论是后来做合成实验时才得到的。所以那些图的暗部
> 可能带有最多约 1 档的假偏色；同一批数字里的 γ、偏移与残差不受影响（它们与
> 截断无关）。当前程序一律取 2.5。

## 三、「同卷、同光源、同一次扫描」各自在防什么

README 里给的是结论，这里补推导。前提是一个模型：把灰卡各级灰在负片上的密度对曝光画出来，
三个通道各得到一条直线

```
Pi_c = o_c + γ_c · L
```

**方向（γ）是链路的属性，位置（o）由零点决定。** 由此可以逐条判断那三个「同」的硬度。

### 解 γ 时，零点准不准无所谓

零点给每个通道加的是一个常数（`−log10(t0_c)`），而秩 1 分解的第一步就是去掉每列的均值 ——
常数被消掉了。所以在拍卡那一帧上，片基点得偏一点，解出的 γ 分毫不差。

（数值上验证过：同一组灰阶数据，`t0` 分别取该列的**最小值**与**最大值**，解出的 γ 完全一致。）

### 用 γ 时，零点必须准，而且两帧的零点误差要一致

把标定帧记作 A、使用帧记作 B，零点误差记作 `err_c = D0_c − D0'_c`（真实片基密度减你假设的）。
推导下来，B 帧的残留偏色是

```
(out_c 三通道之差) ∝ ( err_B,c − err_A,c ) / γ_c
```

于是：

- 两帧都是真片基 → 两项都是 0 → 中性；
- 两帧都错得一样 → 相减抵消 → 中性；
- 一个偏 0.2 档、一个偏 0.5 档 → 差值留下来变成偏色，**而标定救不了它**。

### 三条「同」的硬度

| 要求 | 机理 | 硬度 |
|---|---|---|
| 同一光源 | 光源光谱是 `γ` 的自变量之一，换灯就是换链路 | 最硬 |
| 同一次扫描（同一批） | 同一批里扫描仪的灯与店家设的自动白平衡不变，等价于「同一条链路」 | 硬 |
| 同卷 | **不影响 γ**。它的作用是让 `err_A ≈ err_B`，即上面第二种情形 | 软，是拿不到片基时的补救 |

**所以正解不是「每卷拍卡」，而是「每一帧都看到未曝光片基」。** 做到这一点，`err` 恒为 0，
跨卷、跨批（只要链路没变）都不必重测 γ。

顺带一个有用的推论：**标定帧自己的零点也必须准**（`err_A ≈ 0`）。如果标定帧是拿
「画面最亮 0.05%」凑的、而那片最亮处其实是灯箱，那么 `err_A` 会被烤进标定里，
之后每一帧都带着同样大小的偏色 —— 这正是相机翻拍件最容易翻车的地方。

## 四、为什么只要灰、不要彩色

### 4.1 去色罩本身是逐通道的，通道之间不说话

去色罩这一步的模型是：

```
Pi_c = o_c + γ_c · L          c = R, G, B
```

三个通道各有一条自己的直线，**彼此之间没有任何交叉项**。橙色色罩在数学上就是
「每个通道有自己的底密度、自己的斜率」，仅此而已。所以未知量只有
**三个偏移 o、三个斜率 γ，外加一个参考点** —— 跟颜色空间、色彩矩阵、色域一点关系都没有。

### 4.2 灰块给的是「三通道共享同一个曝光」这条约束

数一下未知数就清楚了。对任意一块被测物，我们量到三个数 Pi_R、Pi_G、Pi_B。

**如果它是彩色的**：它的反射光谱在不同波段不一样，所以三个通道接收到的曝光
L_R、L_G、L_B 是**三个互不相干的未知数**。于是：

```
3 个方程，3 个未知数（L_R、L_G、L_B）—— 刚好用完，一点剩余都不留给 γ 和 o
```

再加一块彩色块，无非再多三个未知数。**无论拍多少彩色块，都解不出 γ。**

**如果它是中性的**：不管它有多亮，它的反射光谱是平的，三个通道接收到的是
**同一个数 L**。于是：

```
3 个方程，1 个未知数 —— 多出两个约束，它们只能被 γ 和 o 吃掉
```

**这才是灰卡的价值所在：不在「灰」这个颜色，而在「三通道的曝光是同一个数」。
灰卡上每一级灰，都在给 γ 和 o 加两个约束。** 所以要点 ≥2 块、亮度要拉开 ——
每多一块多两个约束。

### 4.3 用实测数据验证：彩色列在秩 1 检验下立刻现形

第八轮在 SpyderCheckr（48 格）上做过一次完整的检验：把它按列分组，
每列单独做秩 1 分解，看 σ₂/σ₁：

| 列 | σ₂/σ₁ | 秩 1 残差 | 判定 |
|---|---|---|---|
| 左 4（中性灰阶） | **3.98%** | 0.0397 D | 通过 |
| 右 1（中性灰阶） | **4.92%** | 0.06 D | 通过 |
| 左 2（中性灰阶） | **5.58%** | 0.0724 D | 通过 |
| 右 4（彩色） | 26.87% | 0.3959 D | 不通过 |
| 左 3（彩色） | 29.68% | 0.1846 D | 不通过 |
| 右 3（彩色） | 43.88% | 1.1286 D | 不通过 |
| 左 1（彩色） | 48.77% | 2.0759 D | 不通过 |
| 右 2（彩色） | 58.53% | 5.0725 D | 不通过 |

**三列灰的 σ₂/σ₁ 都在 6% 以下，五列彩色的全在 27% 以上 —— 中间没有过渡。**
这不是巧合：彩色列本来就不满足「三通道共享同一个曝光」这个前提，
秩 1 分解必然解不动。检验指标干净利落地把它们分开了。

顺带一个有用的副产品：**三列互相独立的灰给出的 γ 一致到 4% 以内**。
这是一次交叉验证 —— 单列做不到这件事。所以买卡时，多列独立灰阶是一个加分项
（它检验的是「卡本身做得匀不匀」）。

### 4.4 那彩色块是干什么用的？—— 它解决的是另一个问题

彩色块能解的是**颜色准不准（ΔE）**，不是**色罩去没去干净（中性）**：

| | 去色罩 | 颜色准确 |
|---|---|---|
| 要回答的问题 | 中性吗？线性吗？ | 色相/饱和度像不像原景？ |
| 需要什么 | **中性**参考（谱平的反射体） | 已知光谱/色度值的彩色靶 + 光源光谱 + 器材光谱响应 |
| 得到什么 | γ、o、零点 | 3×3 矩阵 / 高阶多项式 / 3D LUT（DCP、ICC） |
| 成本 | 一两格胶片 | 透射色靶 + 光谱实测 + 建配置文件 |

**两件事必须按这个顺序做**：先去色罩（把负片变成中性、线性的正片），
再做颜色变换。反过来做，等于在一个还带着强烈逐通道偏移的数据上拟合矩阵 ——
色罩那三个巨大的偏移会把这几个自由度先吃掉，矩阵根本立不住。

工业界的对应关系也是分层的：负片先扫成**印片密度**（相当于去色罩这一步），
再由 **IDT** 映射到 ACES（设备表征），最后由 **ODT** 给出观感。颜色变换在 IDT/ODT 那一层，
不在去色罩这一层。

### 4.5 一句话

**灰卡管中性，彩卡管颜色。** 中性是颜色的必要条件，不是充分条件 ——
所以「中性对了」不等于「颜色对了」，那两笔钱要分开花。
