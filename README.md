# NegLab · 去色罩工作台

> 把彩色负片扫描件反相成**中性、线性**的正片。只做一件事：**把「参数」从猜变成可测量。**

macOS 桌面应用 · 零安装（复用系统 Python 3.11 自带的 PySide6/cv2/numpy）· MIT

---

## 30 秒版

```bash
git clone <this repo> && cd neglab-oss
bash tools/build_tools.sh            # 编译 raw 转换器（可选，只有拍 raw 才需要）
python3 app/build_app.py             # 生成 NegLab.app
open NegLab.app
```

打开一张负片 → 点一下片基定零点 → 点几块中性灰 → 按「解算 γ」→ 导出 16-bit 线性 TIFF。

**三步，一分钟。**

# 一、为什么要做这个

市面上的胶片反相工具（darktable 的 negadoctor、DiVERE、SpektraLab、Negative Lab Pro…）
算法都不差，问题在**参数**：

| 它们怎么做 | 结果 |
|---|---|
| 把逐通道斜率 γ 写成**固定常数**（negadoctor 硬编码 4.0；Cineon 固定 0.6） | 换一支胶卷、换一台机器就不对了 |
| 让你**手搓滑杆**试 | 没有判据，只能"看着顺眼" |
| 完全**闭源** | 你无法知道它到底做了什么 |

而我们实测发现：**从画面里猜这个参数，红通道 0.738 / 蓝 1.770；从灰阶卡上读出来是 0.933 / 1.626 ——
差 0.34 档。而所有方法之间的差异只有 0.1~0.3 档。**

> 也就是说：**把参数测对，比换一整套软件更值钱。**

NegLab 就是把这件事做成一个能点的东西。

# 二、原理（小白版，看完就懂）

### 1. 为什么不能简单地「1 减 T」

负片是**密度**，不是亮度。密度 D 和透过率 T 的关系是

```
D = −log10(T)          T=0.1 → D=1.0
```

所以「直接把亮度反过来」在数学上就是错的。正确的反相是**先转密度、处理、再转回来**。

### 2. 色罩（橙色色罩）到底是什么

C41 彩色负片上那层橙色，是**品红和黄色染料**的固定残留 —— 每个通道都垫了一层底。
它的物理后果是：

- **蓝通道被压得最狠**（片基处透过率常常只有 14%）
- 三个通道的**感光-显影曲线斜率不一样**（这就是 γ）

NegLab 实测某卷真实胶片：片基密度 **R 0.27 / G 0.60 / B 0.85** —— 蓝是红的三倍多。

### 3. 核心三行

```
Pi_c  = −log10( T_c / T0_c )        ① 相对「零点」的密度
L_c   = ( Pi_c − o_c ) / γ_c        ② 逐通道曝光坐标
out_c = 10^( (L_c − L_ref) / 0.6 ) − 1    ③ 反相
```

- **T0（零点）** = 「零曝光」落在密度轴的哪里。**每帧都要定。**
- **γ（斜率）** = 逐通道密度斜率比。**一次性**，管一个「胶片型号 × 扫描/翻拍链路」。
- **o（偏移）** = 和 γ 一起解出来。

### 4. 怎么测出 γ —— 秩 1 分解（这是整套东西的关键）

在一段**中性灰**上（比如灰阶卡的 6 级灰），设第 k 级的曝光是 L_k，那么：

```
灰块 k 在三通道上的密度：  Pi_R(k) = o_R + γ_R · L_k
                          Pi_G(k) = o_G + γ_G · L_k
                          Pi_B(k) = o_B + γ_B · L_k
```

左右两边对 k 来说，**L_k 是与通道无关的同一个数**。所以把这 N×3 的矩阵**去掉每列的均值**之后，
它应该是**秩 1** 的。做一次 SVD 就同时得到：

| 从 SVD 里拿到的 | 是什么 |
|---|---|
| 右奇异向量 γ | **逐通道斜率比**（这就是我们要的量） |
| 每列的均值 o | **逐通道偏移**（白平衡） |
| 第二奇异值 / 第一奇异值 | **这批点够不够中性**（σ2/σ1，越小越好，<6% 算合格） |

**你不需要知道那几块灰的绝对亮度** —— 只要它们确实是中性的。

> 顺便：RawTherapee 的 Film Negative 用的是**同一个数学**（它的 Red ratio / Blue ratio
> 就是 γ_R/γ_G 和 γ_B/γ_G），只不过它固定让你点 2 块。NegLab 用秩 1 分解，
> **你点几块就吃几块**，每多一块多两组约束，更稳。

### 5. 为什么零点必须每帧定

`T0` 是「零曝光」的位置，也就是**未曝光片基**。而绝大多数店扫件为了好看，
会把画面**裁到正好 36×24mm** —— 片基、齿孔、边码全剪掉。

于是你只能拿「画面里最亮的像素」当代理。而它**是不是真的片基、是不是中性**，取决于那一帧拍了什么。
我们实测：**同一卷之内，零点就能漂 0.37~0.49 档**，比所有方法之间的差异还大。

**所以最值钱的一条改进是：跟店家要「不裁到画幅内」的扫描。** 免费。

# 三、手把手：从冲扫到成品

## 第 0 步：决定用什么数字化

**先说反直觉的结论：决定成败的不是"用什么机器"，而是"最后拿到什么格式的文件"。**

| 方式 | 优势 | 代价 |
|---|---|---|
| **店扫**（诺日士 HS-1800 / 易麦康 X5…） | 平整、均匀、分辨率高、有 ICE 除尘、快 | 默认输出 8-bit / sRGB / 裁到画幅内 —— **恰好把你要的三样全剪掉** |
| **自己翻拍**（相机 + 光源 + 片夹） | **你完全掌控**：16-bit、线性、不裁画幅、一次拍 raw | 要买器材，要处理反光与平整度 |

**判断标准：店能不能给到你要的文件。**

- 能给 → **选店扫**（画质更稳）
- 不能给 → **选翻拍**

> 实测对比：8-bit 店扫件的蓝通道「唯一值」只有 **89**（≈5.6 bit）；
> 自己翻拍 raw 转出来的 16-bit 线性 TIFF 是 **52788**。差两个数量级。

## 第 1 步：跟店家要什么文件

可以直接复制这段话发给店家：

```
这卷底片想尽量保留原始信息，麻烦按下面扫描：
① 16-bit TIFF，不要 JPEG
② 线性输出，不要套任何色彩空间或显示曲线
③ 不要反相（按正片/反转片模式扫，看起来"橙橙的"是正常的）
④ 关掉所有自动项：自动对比度 / 色彩平衡 / 锐化 / 颗粒抑制
⑤ 【最重要】不要裁到画幅内，把片基、齿孔、边码一起扫进来
⑥ 我拍了一张灰阶卡，麻烦让它和画面用完全一样的参数一起扫出来
```

**按优先级争取，争到哪一步算哪一步：**

```
★★★  不裁画幅（保留片基）    ← 最值钱，而且免费
★★★  16-bit
★★   不反相
★★   线性（不套 sRGB）
★     关掉自动项
```

### 拿到文件先体检

```bash
python3 tools/demask_pipeline.py check <文件夹>
```

| 读数 | 阈值 | 含义 |
|---|---|---|
| 蓝通道唯一值 | **< 100 → 停** | 这个通道已经被量化抠死，任何算法都只能猜 |
| 撞密度上限的像素比例 | **> 10% → 警告** | 高光或暗部有整片损失（实测最坏的一帧 21.2%） |
| 零点漂移（整批极差） | **< 0.35 档 → 可共用标定** | 0.35~0.8 要逐帧核对；> 0.8 不能共用 |

## 第 2 步：自己拍一张灰阶卡

**只需要灰。** 不是 24 色卡 —— 24 色卡买的是「颜色像不像」，而色罩问题是「中性 + 线性」，只需要灰。

### 用什么卡

| 卡 | 够用吗 |
|---|---|
| **Datacolor SpyderCheckr（48 格）** | ✅ 自带**多条**中性列，最省心 |
| **ColorChecker Classic（24 格）** | ✅ 底部有一整行 6 级灰阶 |
| 自己打印一段灰阶阶梯贴在卡纸上 | ⚠️ 能用，但纸张反光会让精度打折 |
| 随便拍一块 18% 灰卡 | ❌ **能钉偏移、钉不了斜率**（你会看到中性对了，但亮部暗部还在往两边偏） |

### 三个硬要求

1. **和画面同卷、同光、同一次扫描。** 最省的做法：**每卷开头占用 1~2 格**。
2. **卡要完整出现在画面里。** 店把画幅裁到 36×24mm 就会把它切掉 —— **这是流程里最容易断的一环。**
3. **级数要覆盖 片基 → 接近 Dmax。** 6 级够，12 级更稳。

> **换光源（RGB 窄谱 ↔ 宽带白光）等于换链路，γ 要重标一次。**

### 什么时候要重做 γ

| 情况 | 要不要重拍 |
|---|---|
| 换胶片**型号** | **要**（Gold 200 和 Portra 400 的 γ 不同） |
| 换店 / 换机器 / 店家改设置 | **要** |
| **换光源** | **要** |
| 同型号 + 同店 + 同批冲洗 | **不用** —— γ 不会变 |
| 每卷头拍 1~2 格 | **这是保险，不是数学必需。** 保险的对象是「店家暗地里换了药水，而你收不到通知」 |

## 第 3 步：用 NegLab 去色罩

打开 `NegLab.app`，四步：

### ① 打开负片
拖进去，或 ⌘O。支持 16-bit 线性 TIFF、8-bit TIFF/PNG/JPG；
相机 raw（ARW / CR3 / NEF / DNG / RAF…）会**自动**调用随包的 `raw2linear` 转成 16-bit 线性 TIFF。

> **raw2linear 做了什么**：用 macOS 自带的 Core Image RAW 解码器，并且把
> 「相机默认外观」全部关掉（对比度 S 曲线 / 饱和度 / 高光恢复 / 局部色调映射 / 阴影提亮）。
> **为什么必须关**：这些是按通道施加的非线性变换，会扭曲「逐通道密度斜率」—— 而那正是我们要测的量。

### ② 定零点（每帧都要）
- **有未曝光片基？** 点「点片基」，在齿孔区/帧边透明条上点一下。**最准，而且帧帧独立。**
- **没有片基？** 先用「画面最亮 0.05%」，但记住它会被「这帧最亮的东西是什么颜色」带偏。

### ③ 解 γ（一次性）
1. 点「点中性灰」
2. 在负片上的灰块中央点几下（**≥2 块，亮度要拉开**）
3. 按「解算 γ」

软件会告诉你 **σ2/σ1**：
- **< 6%** → 这批点够中性 ✅
- **> 6%** → 换几个位置重点，或检查零点对不对

点错了按 ⌘Z 撤销。

### ④ 看读数、导出
**唯一的验收标准**是读数面板里的最后一段：

```
── ★ 验收：你点的那些灰还剩多少偏色 ──
  0.0264  0.0128  0.0192  0.0385  0.0402  0.0486   档
  最大 0.0486 档  ✅
```

这一栏是**唯一能判对错**的东西。下面那行「中间调偏色」**不能**用来判对错 ——
因为画面里没有已知中性面，那个数字量的是场景自己的颜色。

## 第 4 步：导出与后处理

- **16-bit 线性 TIFF（⌘E）** —— 这是母版。丢进 DaVinci Resolve / Lightroom 继续分级。
- **8-bit JPEG** —— 只想快速看效果时用。

# 四、常见问题

<details><summary><b>NegLab 是不是比 negadoctor 更科学？</b></summary>

**反相算式上不是。** NegLab 用的就是 Cineon 家族那三行；negadoctor 在已知中性灰阶上是 0.75 档，
而这条式子配上好参数大约 1.5 档量级。

**NegLab 赢的是「参数可以变成测量」。** 如果零点靠猜、γ 也没测，它不会比 negadoctor 更好，可能更差。
给对参数，它才发挥。
</details>

<details><summary><b>我的店扫件是 8-bit sRGB、裁到画幅内的，能用吗？</b></summary>

能读，但**救不回来**。
- 8-bit 的密度量化台阶约 **0.0248 D**，是 16-bit 的约 80 倍粗
- 蓝通道唯一值常常只有 ~89（≈5.6 bit）
- 没有片基 → 零点只能猜

体检面板会直接告诉你「某通道唯一值只有 89，别再往下做了」。**换文件比换软件重要。**
</details>

<details><summary><b>非得拍灰阶卡吗？</b></summary>

不然呢？你只有两个选择：
① 用 **RawTherapee 的 Film Negative**（参数一一对应，但**只支持 raw**，店扫 TIFF 用不了）
② 用 **darktable negadoctor / DiVERE / SpektraLab / NLP**，接受 γ 是内置常数或靠手搓

灰阶卡的成本是一两格胶片。**这是整条链里性价比最高的一步。**
</details>

<details><summary><b>灰阶卡要买 24 色卡吗？</b></summary>

**不用。** 色罩问题只需要灰。24 色卡多买到的是「颜色准不准」和「染料串扰矩阵」——
那是**颜色**问题，不是**色罩**问题。

要颜色可复现（跨卷/跨时间出同一个颜色）才需要：**透射**色靶 + 光谱实测 + 建 DCP（Lumariver 那条路）。
</details>

<details><summary><b>「未曝光片基」和「边码」是干什么的？</b></summary>

| | 是什么 | 干什么 | 需要知道型号吗 |
|---|---|---|---|
| **未曝光片基** | 完全没曝光的透明区 | **光度零点** —— 定义密度轴的原点 | **不需要** |
| **边码**（`FUJI 200` / `10A`） | 片边印的字符 | **身份识别** —— 选胶片档案 + 归档 | 它就是答案 |

两者不是一回事。片基是**测量**用的，边码是**元数据**。

附带好处：片基在画面里，你能**当场判断通道有没有被扫爆**。
</details>

<details><summary><b>为什么 raw2linear 要关掉那么多东西？</b></summary>

因为相机的「默认好看」是按通道施加的非线性变换。开着它，
你测到的 γ 里混着相机的 S 曲线 —— 那就不是胶片的 γ 了。

`inputBoost = 0` 是最关键的一个：官方注释写「0 表示无 boost，即线性响应；默认 1，完整 boost」。
实测：boost=0 时中位数 0.105，boost=1 时 0.208 —— 差了整整一档的渲染。
</details>

<details><summary><b>为什么 .app 只有 200 KB？</b></summary>

因为它不自带 Python 和 Qt，而是复用系统 Python 3.11（python.org 版）里已经装好的
PySide6 / cv2 / numpy。比 py2app 打包（几百 MB）省得多，也不会在 Qt plugin 路径上翻车。

前提：你要装过 [python.org 的 Python 3.11](https://www.python.org/downloads/) 并且
`pip3 install PySide6 opencv-python numpy`。
</details>

<details><summary><b>Windows / Linux 能用吗？</b></summary>

核心算法（`app/neglab.py` 里的 `fit_gamma` / `invert`）是纯 numpy，跨平台。
命令行工具（`tools/demask_pipeline.py`）也跨平台。
但 GUI 打包脚本和 `raw2linear` 是 macOS 专用的。
</details>

| 项目 | 数字 |
|---|---|
| 8-bit 店扫件的蓝通道 | 唯一值 **89**（≈5.6 bit），密度台阶 0.0248 D |
| 翻拍 raw → 16-bit 线性 TIFF | 唯一值 **52788** |
| 从画面猜 γ（红 / 蓝） | 0.738 / 1.770 |
| 从灰阶卡读 γ（红 / 蓝） | **0.933 / 1.626** |
| 两者之差 | **0.34 档**（而所有方法之间的差异 0.1~0.3 档） |
| 灰阶卡六点中性残差 | **≤ 0.049 档** |
| 同卷之内零点漂移 | **0.37 ~ 0.49 档** |
| 片基估错一倍 → 结果错 | **5 ~ 10 档** |
| PI_CLIP 取 1.8 制造的假偏色 | **1.08 档**（取 2.5 时为 0） |

## 外部依据（都对上了）

| 我们的做法 | 依据 |
|---|---|
| Cineon：片基=code 95、参考白=685、0.002 D/code、负片 γ=0.6 | Kodak《Color and Mastering for Digital Cinema》 |
| 逐通道指数模型 `Pi_c = o_c + γ_c·L` | **RawTherapee Film Negative 的源码级模型** `R = R^rexp × rmult`，`rexp = refexp × rratio` |
| **γ 一次性、零点每帧** | RT 官方文档「每卷点一次，可拷给同卷其它照片」；RT 作者「系数与白平衡是完全不同的东西，系数对整卷不变，白平衡每帧不同」 |
| 在胶卷头几格拍色卡 | RT 作者的建议 |
| 点太少会把系数带偏 | RT 作者：「两点靠得太近时颗粒噪声会引入大误差」 |

五项：合成往返 / 跨帧代数 / 真实灰阶 / 截断量化 / 单调性。**改任何代码后都该跑一遍。**

## 开发者注记（踩过的坑）

<details><summary><b>① 打包 .app：LaunchServices 会跑到 Rosetta 下</b></summary>

双击 shell 脚本启动器时，LaunchServices 会把它放到 **x86_64（Rosetta）** 下跑，
而 python.org 的 numpy 只有 arm64 切片 →

```
ImportError: mach-o file, but is an incompatible architecture (have 'arm64', need 'x86_64')
```

**直接跑 `Contents/MacOS/NegLab` 不会踩，只有双击才踩。**
解法：启动器里显式 `arch -arm64 "$PY" ...`。
排查手段：让启动器把 stdout/stderr 追加到 `~/Library/Logs/NegLab-launch.log`
（LaunchServices 会把输出丢掉，不写文件就什么都看不到）。
</details>

<details><summary><b>② raw2linear：属性名要用运行时反射出来的那套</b></summary>

`CIRAWFilter` 的 ObjC 头文件里写的是 `draftModeEnabled` / `contrastAmount`…
但实际实现类 `CIRAWFilterImpl` 用的是 CIFilter 的 **`input*`** 命名。
照头文件写的结果是「**生效 0 项、忽略 21 项**」—— 相机外观一点没关掉。

反射命令：

```objc
Class c = [f class];
unsigned n = 0; Method *ms = class_copyMethodList(c, &n);
for (unsigned i = 0; i < n; i++)
    if (strncmp(sel_getName(method_getName(ms[i])), "set", 3) == 0)
        printf("%s\n", sel_getName(method_getName(ms[i])));
```
</details>

<details><summary><b>③ 三个「看起来是 bug，其实是度量错」的坑</b></summary>

- **三通道的 L 绝不能取中位数** —— 取了输出就是一张灰图。
- **跨帧搬运标定时，偏移 o 与 L_ref 是常数，不要做「平移」**。
  代数上 `L_c − L_ref = L − L0_B` 对三通道相同 → 天然中性；
  每帧的零点是通过 `Pi` 自己进去的。加平移反而会引入偏色。
- **拿 log 量「比值的极差」前，先确认分母不为 0**。
  片基那一行输出恰好是 0，`log2(0)` 会给出假的天文数字
  （旧写法把 Cineon 在某一卷上的漂移算成 34.8 档，真值 2.4 档）。
</details>

<details><summary><b>④ macOS 文件系统大小写不敏感</b></summary>

`rm -rf neglab` 会把 `NegLab/` 一起删掉。**别在同级目录里用只差大小写的名字。**
</details>
